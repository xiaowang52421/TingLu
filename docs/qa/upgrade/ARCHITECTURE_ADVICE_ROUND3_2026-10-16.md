## S1 · 证据目录的"空目录"是**跨 stage 的系统性空隙**，且未被 E-E5 覆盖 ⭐⭐

  | `20261016-032608-6ee7a91a` | 15 | ✅（PlayMode 2/2） |
  | `20261016-032618-52d30ea5` | 0 | ❌ |
  | `20261016-032724-5d2663cb` | 0 | ❌ |

  （同类空目录在更早时段亦存在：`023336-fa2c4e02`、`023430-37955fea`、`023510-34f5162b`；`texture-comparison` 亦为空。）

- **判读（谨慎）**：回复稿称 **E-E5 已解决**，指的是 `Verify-StreetPlayer.ps1` 把 EXE 解析移入 `try`、由 `finally` 写报告——**该修复本身成立**。但上述空目录提示：**"创建证据目录"与"写出 `results.json`"之间仍存在空隙，且不限于 Player 一种 stage。** 回复稿未声称这些空目录已被修复，故本项按**未处置**提出。

- **建议**：把"**只要创建了 evidenceRoot，就保证有 `results.json`**"提升为**不分 stage 的统一不变量**——在脚本最外层加一个 `finally`，对未写出报告的证据目录写 `NOT_RUN` + 原因。

- **理由**：空目录是**不可审计状态**——事后无法判断那次运行是未启动、启动即崩、还是被跳过。这与 A5 / F-F3 已确立的"不可归因的记录不得当依据"是同一原则。

- **成本**：低。
- **证据与核对方式**：`Get-ChildItem output/unity-verification/*`（现读，2026-10-16 03:32 前后）；`Verify-StreetPlayer.ps1:14-22,79-83`（静态源码，现读）。

## S2 · `TextureAxis` 修复需要一条"**记忆合并前后方向不变**"的测试 ⭐⭐

- **观察**：新方案为 `TextureAxis = Canonical(textureAxis ?? ForSurface(material, Polygon))`——**从表面自身的多边形派生方向**（`StreetContracts.cs:40-44,161-165`）。
- **风险**：Memory 合并相邻碎块时**会重建多边形** → **派生的方向可能随之改变** → **贴图方向在合并发生的那一刻跳变**。
- **为什么静态目检覆盖不到**：目检只能看到某一时刻的方向，**看不出方向在合并瞬间的跳变**。
- **建议**：新增一条测试——**在同一地点跨一次 Memory 合并，断言 `TextureAxis`（或等价的渲染 UV 轴）保持一致**。
- **理由**：本项与已修复的 `LongestEdgeAxis`、以及 `Degenerate polygon` 属**同一类缺陷**：**几何在切割/合并中丢失"表面身份"**。前两次均为"先暴露后定位"，本项可以**先测**。
- **成本**：低。
- **证据与核对方式**：`StreetContracts.cs`、`StreetRenderer.cs:116,229,238`（静态源码，现读）；合并路径见 `StreetMemory.cs`（静态源码；**合并是否重建多边形这一点本稿未逐行确认，标 NOT_VERIFIED**）。

## S3 · 交付包缺少 **HUD / 菜单画面的图像证据** ⭐

- **观察（既有产物实测）**：
  - PlayMode 五图的 `screenshotScope` 明确为 **`Camera.Render` 世界帧，不含 HUD 或菜单**；
  - 复核记录明确写出：`a25-paused.png` **不能用来判断暂停菜单是否正确显示**；`a30-finished.png` **该世界帧不含 HUD 或结算 UI**；
  - 交付目录 `output/听路试玩_2026-10-16_街区复核版/` 存在，`package-manifest.json` 在案。
- **建议**：对交付包补**两张全屏截图**——① 含 HUD 的游玩画面；② 暂停菜单。
- **理由**：**R06**（游戏中无虚拟操作按钮、菜单仍可操作）与 **R19**（不显示脚下文字）是**画面级要求**，而 `Camera.Render` 帧**天然覆盖不到它们**。目前画面类需求中，这是**唯一没有图像证据**的一组——纹理、未知区黑、地面填充均已有图。
- **成本**：低。
- **证据与核对方式**：`PLAYER_IMAGE_REVIEW_2026-10-16.md:9,20,23`（既有文档）；`output/unity-verification/20261016-030730-a823f3ed/street-acceptance/a25-a30-results.json`（既有产物）。

## S4 · B-B2 的"每次精确 +5"建议**换位置复测以定性**

- **观察（既有产物实测）**：`stationary-repeat` 8 次，表面数 206→229→234→239→244→249→254→259→264——**每次精确 +5**；面积自 `164.286204` 至 `164.286212`。
- **观察的意义**：**精确恒定的 +5 不像随机几何碎片化**，更像来自**固定数量的分片规则**。
- **建议**：把静止重复测试**换到另外几个位置**（贴墙、贴路缘、开阔人行道各一），观察增量是否为常数 5：
  - **随位置变化** → 属几何性质，按 B-B2 长期观察即可；
  - **恒为 +5** → 说明存在**每次重复都重建固定数量碎片**的结构性浪费，属可直接消除项而非几何必然。
- **理由**：本项可把 B-B2 从"长期观察"推进为"**可定位的具体机制**"，成本仅为调整探针位置。
- **成本**：低。
- **证据与核对方式**：`20261016-030510-2781e2d0/street-acceptance/probe-performance-*.json` 的 `stationary-repeat` 段（既有产物实测）。

## S5 · C-C2 的门槛需先把"代表路线"固化为可重跑 fixture

- **观察**：回复稿认可"先记录基线并定义代表路线/机器口径，再选宽松门槛"。当前 13 样本为"真实路线 5 次 + 西侧检查点静止重探 8 次"，**该序列本身未命名、未固化为断言**。
- **建议**：在定门槛**之前**，把该序列固化为**可重跑的 fixture**（固定起点、固定步数、固定探针序列），使其成为可复现的测量口径。
- **理由**：否则门槛会退化为"每次跑出的数字不同"，无法作为回归依据。
- **成本**：低。
- **证据与核对方式**：`PROBE_PERFORMANCE_2026-10-16.md`（既有文档）；`probe-performance-*.json`（既有产物）。

## S6 · 音频池拒绝的上下文建议**落成数据**，使"丢没丢声"可判定

- **理由**：这是当前**唯一一处"已知有问题但严重程度未知"**的开放项；补一个字段即可定性。
