# 街区升级架构与接口计划

本文件是设计计划。下面的接口语义尚未实现或发布；现有正式契约版本为 0.2.0。主控必须核对现有代码后确定唯一声明，不允许各角色复制公共类型。

## 现有工程事实

- Unity 2022.3.62f1c1、Built-in 渲染、Input System 1.7.0。
- 输入动作当前缺少独立朝向；PlayerController 当前用移动向量更新朝向。
- DemoEntry 承担键盘/手柄/触屏采样、俯视相机、按钮覆盖层和模块装配。新职责应下沉组件，再由主控接线。
- 当前敲杖 payload 主要传半径，需显式携带发出时的位置、朝向和角度。
- MemoryPolicy 只有 Never/ConfirmedStaticGeometry，不能用此旧枚举直接假装支持临时记忆。
- WorldRegistry、Perception、Memory、VoiceRenderer、LevelCompiler 与 LocalSaveService 已存在，应增量演进。
- 旧首关通过了历史验证；升级后的通过状态需重新实测，不能继承旧报告为新证据。

## 信息链路

真实世界/材质/交通 → 声学查询 → 合法被动听觉观测 → 短时声纹。
鼠标朝向 + 右键 → 扇形请求 → 遮挡裁剪 → 实际覆盖 + 局部观测 → 永久探索/临时记录 → 已知画面。
真实世界 + 角色移动 → 真实碰撞 → 普通反馈或车辆恢复 → 检查点事务。
存档只保存允许的持久数据与旧记录，重新进入后重算活动感知。

Presentation 不查询完整世界来补画道路、墙体、影子、碰撞提示或声源轮廓。Camera 只接收角色位置、朝向、配置，不获取地图真值。

## 2.5D 与坐标

保留纯 C# 的 Point2 玩法平面；推荐将它映射到 Unity XZ 地面，使用固定斜俯视正交相机，展示建筑高度/轮廓和简化地面纹理。此为推荐，不是已完成的引擎迁移。

00 必须发布坐标转换，07/08 只消费转换接口，避免声源、镜头、地面和碰撞各自换轴。既有音频曾采用 (x,0,y)，应核查沿用条件。若复用 XY 展示更合适，也必须达到固定斜俯视 2.5D 并保证四方向一致，不能只把旧俯视相机斜放而放弃遮挡正确性。

G0由00同时冻结固定镜头方位与WASD平面基向量。01直接消费此映射，不等待07实现；07消费相同映射并验证实际相机投影，不重新定义另一套基向量。06使用G0声音目录和声学fixture启动，不以09最终地图为前置；09同样依目录配置，最终声音与地图在G2联调。

声学结果的唯一生产者是06，统一观测帧的唯一生产者是04，展示消费者是08；这是两个不同层次，不允许06和04各产一份活动观测流。04的几何探测可用G0的IAcousticQuery替身独立测试，真实听觉接入要等06交付，禁止绕过04把声学查询结果直接传给渲染。

06计算并冻结采样时刻的候选声源位置、声学可辨类别等结果；04只按许可、有效性与共享规则过滤，复制已获准的位置/类别，并赋予观测来源和有效期。04不再查询世界重算该位置、推断额外类别或重复声学定位；复用值字段是分层传递，不是第二套真值生产者。

地面贴图、物体上部、阴影、描边、灯光与后处理都不能越过合法覆盖泄露未知环境。前景建筑可以根据已知几何做淡化，不得使用全图建筑真值构造玩家遮挡效果。

## 关键认知规则

1. 永久环境“全部确认”仅发生于实际扇形覆盖内。墙的一小段进入覆盖，不代表整面墙或整栋建筑解锁。
2. 已确认地面必须保存面积信息，不能仅保存边线来声称完成盲道/人行道/车道材质探索。
3. 临时障碍的“可移动”不是“当前速度非零”。停着的自行车仍是临时；静止的行人仍是活动对象。
4. 临时旧记录不订阅世界对象 Transform。物体挪走、卸载、删除后，未复核区域里的旧快照仍保留。
5. 旧位置确认空置必须依赖实际覆盖减法。发现同 ID 的新位置，不能自动删除其探测范围外的旧位置。
6. 同一次探测先取得采样时刻的世界/遮挡，再生成可证明覆盖，按该覆盖更新记忆，最后生成展示帧；不混用不同帧真值。
7. 声音可从未探索区域到达；声音定位不确认地面，不画对象完整轮廓。无声时不偷偷靠“活动对象”类别定位。
8. 碰撞、脚步材质允许读真值；身体接触仅确认实际接触附近局部，不揭开整区域。脚下触感不自动泄露完整盲道网络。
9. 当前探测显影计时结束，只是亮度状态变化；永久探索和临时旧记录不会按旧 0.8 秒残影一起清空。
10. 内部纹理遮罩可以离散采样，但存档、查询、裁剪和玩家表现不得强制玩法网格。

## 被动聆听迁移

01 不再输出需要用户按住的 ListenHeld。02 的移动、恢复和行动状态需与主动聆听解耦；06 必须持续执行合法声学查询。旧 ActionMode 是否保留为兼容字段由 00 决定，不能靠永远置 ListenHeld=true 草率实现，否则会导致始终低速和专注持续上涨。

新测试关卡默认：移动用原 walkSpeed 并扣原 focusWalkDrain，静止用原 focusListenGain；被动听觉在两种状态下都工作。低专注与混淆按共享模型作用，不得关闭所有车辆必要可听声音。参数沿用仅作运行基线。

## 车辆碰撞与恢复事务

车辆有真实世界路线和碰撞，与显示与否、是否被听见无关。行人/动物/骑行者属于共同的活动声源类别，但只有带车辆危害定义的对象触发车辆恢复。

事故 → 禁止输入和新事故 → 一次失败事件 → 冻结/隔离运行代际 → 恢复世界及信号/车辆路线 → 恢复角色安全位置和资源 → 保留本关累计永久探索并把临时记录降为过时 → 同步声源/监听器 → 重建感知 → 恢复操作。无检查点回安全起点。按现有演出机制恢复即可，不增加未经要求的等待时长。

暂停、读档、切关、退出需停止旧声源、释放鼠标、解除订阅；恢复时不能先开输入再补碰撞世界。出生点与检查点不得处在车流上，必须测试连续恢复不会卡在立即二次碰撞。

## 存档与旧关卡

00 与 10 冻结新的 schema/版本策略，05 导出不可变探索数据，09 提供 levelId/checkpointId 与交通状态定义。副本使用新的存档命名空间或目录，禁止读写原试玩存档。旧存档、旧首关数据与未知未来版本均不得被静默覆盖。

运行时新关卡的数据扩展由 09 执行；不要求旧编辑器可视化新字段。新 schema 不能被旧编辑器打开后静默丢失字段：隔离格式/路径或明确拒绝保存，保留原文件。若需要最小保护，09 向 00 提交范围请求，不开展工作台功能升级。
