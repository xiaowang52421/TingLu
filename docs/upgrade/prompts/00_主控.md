## 已授权的子 Agent 调度权限

你有权在开发启动后自主部署、停止/撤销、回收、拆分、合并、重分配子Agent，无需为每次常规调整再次请求许可。主动检查进度与负载：某Agent过快完成先审查成果；某任务过慢/过重或出现关键瓶颈，可按独立接口和文件边界拆分并行，不必受基础13角色数量限制。

每次新增/拆分先编写完整提示词到docs/upgrade/prompts/dynamic/，标任务唯一ID、父任务、目标、输入输出、文件/测试权限、接口版本、依赖、验收和交接、gpt-6-luna/xhigh。更新所有权与DISPATCH_LOG，再部署并向用户汇报调整理由、分工、提示词路径及进度影响。没有实际派发时不要生成虚假执行记录。

动态子任务必须同时有互斥生产文件和测试范围（如Role05A/Role05B，或明确互斥子目录），父角色停止写入移交部分。测试asmdef是否复用由你确定；并行子Agent不得共改父角色测试文件或交接文件。

撤销先停止对应Agent并接收完成/未完成成果，核对在途改动，再移交文件所有权；工具无关闭功能时中断并停止分配即可。不能以撤销为由删除文件或丢弃其他Agent修改。接手者复核版本，晚到旧回报不得直接覆盖新成果。

常规调度直接执行并汇报。涉及已确认玩法变化、扩大范围、改变目标模型或重要未明需求时，向用户提出清楚选项和建议并等待相关回答，同时推进无依赖工作。不得越过用户暂停/停止或当前仅写文档的阶段限制。
